Subject: [PATCH] fix(discovery): respect refresh TTL in
 ServiceRegistry::get_upstreams

get_upstreams refreshed from the discovery backend on every call
(`should_refresh = true`), while the last_update map was written and
never read. It now refreshes only when the service is uncached, has
never been refreshed, or was last refreshed at least refresh_interval
seconds ago. refresh_interval = 0 keeps refresh-on-every-call.

watch_service no longer builds its backup ticker when refresh_interval
is 0: tokio::time::interval panics on a zero period, and with a zero
TTL every lookup already refreshes. Found by review.

Roadmap UC12.A (docs/planning/ROADMAP.md). Tests added but not run: the
--lib test target does not compile at this commit (unrelated error at
src/runtime/signals.rs:238), and the crate does not build on Windows.

+    /// Whether `get_upstreams` must ask the discovery backend before answering.
+    ///
+    /// True when the service is not cached, has never been refreshed, or was last refreshed
+    /// at least `refresh_interval` seconds ago. A `refresh_interval` of 0 refreshes on every
+    /// call, which was the only behaviour before this TTL existed.
+    async fn needs_refresh(&self, service_name: &str) -> bool {
+        let ttl = Duration::from_secs(self.config.refresh_interval);
+        if ttl.is_zero() {
+            return true;
+        }
+        if !self.upstreams.read().await.contains_key(service_name) {
+            return true;
+        }
+        let last_update = self.last_update.read().await;
+        match last_update.get(service_name) {
+            Some(refreshed_at) => refreshed_at.elapsed() >= ttl,
+            None => true,
+        }
+    }
